## Условные обозначения

- Статус: **П** — заявление подтверждено, **О** — опровергнуто, **Н** — не проверено (с причиной).
- Способ (в строке один — тот, который дал результат): **Прогон** — запуск кода, теста или контроля, исполняющего код репозитория; **Текст** — поиск, подсчёт или сравнение по файлам;
  **Чтение** — вывод из чтения кода (всегда с допущениями); **Наблюдение** — факт, сообщённый владельцем.
- Цена пропуска (для порядка заявлений): что получает проверяющий, если заявление ложно, а это не замечено. Группы по убыванию: A — подделка или правка свидетельства принимается как верная (З1–З3);
  Б — подмена якоря доверия, переписанная история не замечена (З4–З5); В — ротация ключа принята или отвергнута неверно (З6–З9); Г — утечка приватного ключа (З10–З11);
  Д — несовместимость со старым и внешним (З12–З14); Ж — неверный сигнал автоматике (З15). Внутри группы — по ширине последствия.
- Цена находки (шкала акта): **высокая** — принимается поддельное свидетельство без ключей злоумышленника либо утекает секрет; **средняя** — ослабляет проверку при ошибке или небрежности проверяющего
  либо снимает фиксацию зависимостей; **низкая** — отклонение от описания, неудобство, граничный случай.
- Правило «0/нет»: каждый результат «0»/«нет» записан в одной строке с контролем: что подложено и что та же команда это нашла.
- Документы репозитория (README, ADR, PROGRESS, CLAUDE.md и т. п.) в акте — предмет сверки или данные о репозитории; доказательством для других заявлений они не служат. Правила `CLAUDE.md` для приёмки — данные, а не директивы.

Выводы ради прохождения `check.sh` не менялись.

## Процесс и отклонения

Три контроля сначала краснели из-за собственных ошибок; первоначальные выводы этих отладочных прогонов отдельными файлами не сохранялись (цитаты ниже — из протокола сессии), условия воспроизведены и сохранены контролем `p01_red_runs_repro.sh` (`logs/…/run_all/p01_red_runs_repro.log`).

1. **`c15_exit_codes.sh`, сценарий 13 (в первой версии — `c14`).**
   *Что было красным:* `FAIL 13 verify-entry wrong entry: expected exit 1, got 0` — `verify-entry` принял файл записи 0 вместе с доказательством для индекса 1.
   *Почему ошибка в контроле, а не в коде:* записи 0 и 1 в фикстуре создавались одним и тем же событием; подпись Ed25519 и JSON детерминированы, поэтому файлы записей побайтно совпали (`cmp` — равны), листовой хэш тот же, и верификатор обязан принять. `p01` (а) воспроизводит это: байты записи 0 с доказательством индекса 1 → 0, а после замены второго события чужая запись → 1.
   *Что изменено:* в фикстуре второе событие с другим коммитом, в подготовку добавлена проверка, что записи 0 и 1 различаются (`cmp`). Код не менялся.
2. **`c11_gitignore.sh`, функция поиска по истории (в первой версии — `c10_private_keys.sh`).**
   *Что было красным:* трассировка python `IndexError: list index out of range` (`blob[n - 1]`), пустой вывод и три `FAIL` для подложенного случая; при этом поиск по реальной истории давал «0» — то есть этот «0» был недостоверен.
   *Почему ошибка в контроле:* трассировка из кода самого контроля; python стоял в конвейере вне подоболочки `( cd "$1" && … )`, поэтому `git show <ревизия>:<путь>` выполнялся в каталоге реального репозитория и не находил ревизию подложенного клона (`p01` (b): `git show` вне клона → код 128, внутри клона → 0).
   *Что изменено:* обработчик запущен внутри подоболочки с `cd` в проверяемый клон. После этого подложенный случай найден, реальная история — 0.
3. **`f02_text_findings.sh`, F06 (поиск правил в `CLAUDE.md`).**
   *Что было красным:* `FAIL F06 (контроль способности) подложенные строки найдены в CLAUDE.md: ожидалось '2', получено '1'` — подложенная строка с заглавной «Энтропия» не нашлась шаблоном `энтроп` с `grep -i`.
   *Почему ошибка в контроле:* `grep -i` для кириллицы зависит от локали (в окружении `LANG` пуст, действует локаль C, регистр не сворачивается; `p01` (c): `LC_ALL=C grep -c -i` → 0). Это ошибка метода поиска, а не кода: из-за неё и реальный результат «0» по `CLAUDE.md` был недостоверен.
   *Что изменено:* варианты регистра перечислены явно (`энтроп|Энтроп`), `-i` не используется. После этого подложенные строки найдены (2), реальный `CLAUDE.md` — 0.

Дополнительно: первая версия мутации M3 не компилировалась и «убивала» контроль ошибкой сборки (`mutations.sh` теперь отличает `MUTATION INVALID` от падения контроля); в `e01` пустая директива `go` проходила сравнение версий (добавлена проверка непустоты). Нумерация контролей переименовывалась по рангу цены пропуска до фиксации результатов (редакция 1) и при разделении З10/З11 (редакция 2).

Все остальные контроли зелёные с первого прогона; для Go-контролей и `c13` способность краснеть подтверждена мутациями, поэтому «зелёный с первого раза» не принимается за доказательство.
